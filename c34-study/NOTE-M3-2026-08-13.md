## The M2 findings closed in the preceding commit

- **G-M2-1** — `CallLedger` integrity on load: a running seal per entry plus a
  head record of count and head seal; the chain and `seq` contiguity are
  verified on load and every inconsistency raises. Integrity and recovery are
  separated, and integrity wins: an inconsistent ledger is refused, while a
  *wholly absent* one (journal and head both gone) is a loss and is rebuilt by
  cross-run discovery. Deleting the journal while keeping the head is
  indistinguishable from truncation and is refused rather than silently
  recovered. Six dead runs. Stated plainly in the docstring: an
  unauthenticated hash chain detects truncation, corruption and un-resealed
  edits, not a determined forger with write access.
- **G-M2-2** — `write_stop`'s `here` is now required, killing the default that
  caused the incident; an AST test proves no caller relies on one. The gate
  fires on `created_by_suite` **and** `present_but_uncommitted`, the latter
  catching pre-existing residue — the exact incident state a before/after diff
  would have hidden. Git-tracked status is the discriminator between a
  registered milestone output and residue, which is why this milestone's
  `corpus-snapshot/` passes the gate while a dropped STOP marker fails it. One
  dead run constructs the leak in the real study directory.
- **G-M2-3** — a bare `corpus_rule.py` writes nothing; the evaluation log is
  behind `--log` (implied by `--snapshot`). Post-M3 the test asserts the
  stronger form: a bare invocation leaves the committed artifacts
  byte-unchanged and does not dirty them.
- **G-M2-5** — the unreachable profligate branch removed.
- **G-M2-6** — the never-overwrite-a-scored-record guarantee moved to the
  write site, so it holds for every caller by construction.
- **G-M2-4 — DECLINED upstream**, recorded here as instructed. The proposal
  was idempotent re-reservation (a repeated call key consuming no additional
  budget). Declined because the conservative direction is the registered one:
  a reservation is written before dispatch, so a crash between the two counts
  a call that never reached the provider, and the study fails closed at
  exhaustion rather than risking an unrecorded call against a ceiling that is
  never raised. The behavior is documented in `CallLedger`'s docstring and is
  accepted as-is.

`selection-2026-08-13.json`, `index-2026-08-13.json`, `call-ledger.jsonl`
(with its head record) and `gen-cache/`. **That commit is the order-gate

milestone order is: suite green → produce artifacts → commit → suite green
again. A green suite over uncommitted run artifacts is precisely the reading
the gate exists to refuse.
