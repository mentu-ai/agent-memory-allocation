# C28b — Injection-channel returnability

## Claim

Promoted memory content returns through the **push (injection) channel** — it
re-enters an agent's working context by harness-driven injection at a lifecycle
event (the auto-memory recall surfaced as `system-reminder` content; paper §2.2
"policy-push injection"), rather than by an agent-initiated Read. C28 refuted
return through the **pull** channel (agent Reads a promoted memory file: 2/157).
C28b asks whether the channel C28 could not see delivers what the pull channel
did not: memory content used again with **no** Read of its file.

If the injection channel works, it partially rescues the promotion lane — the
value of writing to durable memory would be realized by push, not pull, and the
mentu-finder "return" vision would hold on the push channel specifically. If it
does not, C28's refutation generalizes: promoted memory returns by neither
channel, and the promotion policy is write-only across the board.

## Origin and the seen, barred observation

Generated by C28's aftermath (its 18,780 non-tool memory-file mentions — the
push channel's footprint — set aside by a Read-only instrument) and by the
public hook API's disclosure of policy-push injection (paper §3.1). A
feasibility probe (2026-07-22, sampled, uncommitted) established two facts that
shape this registration: (1) the content-fingerprint instrument **is feasible**
— on 423 sampled transcripts it found 77 memory-content-reuse detections across
49 files and cleanly separated pull from push by Read-presence; (2) in the
retroactive frozen corpus, push-reuse was **zero** (77/77 reuse co-occurred
with a Read). Per the seen-estimate rule, that retroactive 77/0 is
**hypothesis-informing and barred from adjudicating this claim**. It is almost
certainly feature-timing: auto-memory recall postdates most of the 2026-06/07
corpus. C28b therefore adjudicates **forward only**, on the auto-memory-recall
era — same discipline as c26b.

## Operationalization

**Instrument — content-fingerprint reuse (channel-agnostic; validated
feasible)**: for each memory file, extract distinctive ≥8-word shingles from
its body (frontmatter stripped) that occur in exactly one memory file across
the corpus. A **reuse detection** is a distinctive shingle of a same-project
memory file appearing in an **assistant** message of an eligible session. Each
detection is classed **pull** (that session contains a `Read` tool_use of that
memory file's path) or **push** (no such Read — the content arrived by some
non-pull channel, of which policy-push injection is the documented mechanism).
This measures content *reuse*, not the injection event, so it is immune to the
push channel's non-persistence (paper §2.2).

**Adjudication corpus (boundary rule)**: interactive sessions whose first
timestamp is strictly after this conjecture's registration commit. Sessions in
the 2026-07-18 frozen corpus and between it and registration are excluded from
adjudication (they generated the barred 77/0 observation). This program's own
sessions are excluded. Data: session transcripts; the boot-manifest gauge for
per-session memory-index state.

**Unit**: one memory file, observed over its eligible forward sessions
(same-project, first timestamp after the file's creation, excluding the
creating/editing session).

## Predictions (frozen 2026-07-22, before any forward-corpus data exists)

- **P1 (the push channel is live)**: ≥ **15%** of distinct memory files with
  ≥5 eligible forward sessions show ≥1 push detection (content reused with no
  Read). Retroactive was 0%; this is a bet that the auto-memory era changes it.
- **P2 (push is a material share of reuse)**: among all forward
  memory-content-reuse detections, the **push fraction** (no-Read) is ≥ **20%**
  (retroactive: 0 of 77).
- **P3 (index-mediated)**: push detections concentrate in `MEMORY.md`-indexed
  files at ≥ **2×** the per-file push rate of orphan memory files (given ≥20
  orphans with eligible forward sessions) — the injection recalls indexed
  memories, tying push-return to pointer residency.

## Falsification criteria

- Push fraction < **5%** forward with floors met → **refuted**: promoted memory
  returns by neither pull (C28) nor push; the promotion policy is write-only in
  full generality, and the paper's "promotion works via pointer residency"
  line stays withdrawn on both channels.
- P1 met but P2 in [5%, 20%) → **revised**: a push channel exists but is a
  minor contributor; "the injection channel delivers what pull did not" is
  withdrawn.
- Fingerprint matching cannot distinguish distinctive reuse from coincidence at
  the committed distinctiveness threshold, or the forward corpus is below floor
  → **instrument insufficient**, no verdict; the next action is a stricter
  fingerprint or more accrual, not a weaker analysis.

## Known limitations

- **Attribution ceiling**: "push" is "reuse without a Read of that file" — it
  bounds the non-pull channel from above; a fingerprint the operator typed from
  human memory, or content recalled from a *different* copy, would misclassify
  as push. The mechanism (policy-push injection) is the documented and most
  likely source, but this instrument measures the *channel-agnostic residual*,
  not injection directly. Declared, not hidden.
- Single-operator ecosystem (carried from the program; replication invitation
  is the mitigation).
- Reuse is not utility (instrument note limit 3): a restated fingerprint shows
  the content returned, not that it improved the outcome.
- No confidential reverse-engineering source informs this instrument; the
  public hook documentation is the only external reference (paper ref 9).
