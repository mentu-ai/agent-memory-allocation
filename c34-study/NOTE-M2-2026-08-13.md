## How each registered deviation is realized in code

- **D-1 (arm A dropped).** There is no `A_PROMPT`, no flat dump, no `"A"` in
  `POLICIES`; `build_prompt` raises on an unregistered policy. Enforced by a
  test that greps every module for an `A_PROMPT` assignment.
- **D-2 (P3′ symmetric).** `wrong_stop_rate` is computed inside the single
  per-policy loop for every arm in `AGENTIC`. The adjudicating comparison is
  `wsC >= wsB` — ties pass (v2 C-8, v3 G2). C29's asymmetric form is computed
  and reported under `non_adjudicating.c29_asymmetric_P3`.
- **D-3 (P4 on marginal tokens).** `p4` reads `tokens_marginal` only; totals go
  to `non_adjudicating.P4_on_totals_not_adjudicated`, and the adjudicated
  marginal ratios are reported beside them.
- **D-4 (total verdict map).** One precedence chain, first match wins, every
  outcome named. `PARTIAL — HELD OPEN` does not exist in this harness.
- **D-5 (P5 added).** `p5 = p5a and (p5b is not False)`, with both conjuncts and
  the pooled denominator in the top-level headline.
- **D-6 (hydration on both arms).** `harness_lib.hydration_record` takes no
  policy argument — there is no place to put an `if p == "C"`. A missing record
  on a scored B or C run is the `missing_hydration_record` cause, not a zero.
- **D-7 (one corpus, one repository).** Structural, not code: `corpus_rule.py`
  enumerates exactly one tree. Recorded here so the ledger is complete.
- **D-8 (README.md exemption).** `NAMED_EXEMPTIONS = ("README.md",)`, ordered
  last in `CLAUSE_ORDER` so the registered 3/5/4 rejection arithmetic is
  unchanged by the addition. Verified: README.md matches no other clause.
- **D-9 (P5(b) floor).** `P5B_MIN_DENOM = 20`; below it the conjunct is
  `not_exercised`, reported with its denominator, and P5 rests on P5(a).

## Two things this build added beyond the registration, both stricter

Phase-H rule 1 governs both: each ships its dead run in the same commit.

1. `provider_output_not_degenerate` in the smoke audit — a run set whose answers
   are all empty or all byte-identical is not evidence even when every token
   count is healthy. An audit check can only make the gate stricter; it relaxes
   no threshold and touches no verdict criterion.
2. A **fixture-leak gate** in `run_tests.py`. During this build, two
   `STOP-*.json` markers written by tests landed in the real study directory
   because `write_stop` defaulted to the module's own directory. A stray STOP
   marker would have sealed the real adjudication `instrument-insufficient`.
   `write_stop` is now campaign-scoped, the leaked files were deleted before the
   first commit, and `run_tests.py` fails if the suite writes any live-run
   artifact (`runs/`, `call-ledger.jsonl`, `reality-probe.json`, `gen-cache/`,
   `corpus-snapshot/`, `STOP-*.json`) into the study directory.

## Exact commands for M3–M7

Run `python3 run_tests.py` before and after every milestone. All commands run
from `analyses/c34-public-curation-vs-search-replication/`.

**M3 — corpus snapshot** (no provider call):

```
python3 corpus_rule.py --snapshot
```

Writes `corpus-snapshot/` (141 files, full bytes, relative paths preserved),
`corpus-manifest.json` and `rule-R-evaluation-log.json`. Commit all three.

**M4 — reality probe, then question freeze.** Correction v2 C-5 moves the probe
**ahead of** the BUILD's M5 placement: availability is bought before the
generation budget is spent.

```
python3 run_policies.py --stage probe      # 2 calls; must print probe_passed
python3 generate_questions.py              # <=170 + <=45 calls
python3 build_index.py                     # <=170 calls
```

Commit `reality-probe.json`, `questions-2026-08-13.json`,
`selection-2026-08-13.json`, `index-2026-08-13.json`, `call-ledger.jsonl` and
`gen-cache/`. **This commit is the order-gate boundary**: any policy-run record
whose `started_at` precedes it voids the run set.
